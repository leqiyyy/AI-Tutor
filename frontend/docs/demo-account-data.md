# Demo Account Data Notes

## Purpose

这份文档用于说明“演示账号模式”下，前端当前依赖哪些 mock 数据，方便后端后续决定：

- 是继续由后端返回 demo 数据
- 还是只在前端本地保留 mock

---

## 1. Demo Account Goal

演示账号的目标不是“所有数据都真实”，而是：

- 页面能完整展示主要功能
- 所有关键交互都能走通
- 老师、学生、管理员三个角色都有可演示内容

---

## 2. Student Demo Account

建议角色：

- 学生账号 1：学习中，有课程、有通知、有错题、有闪卡
- 学生账号 2：空状态账号，用于验证零数据展示

建议最少返回：

- Dashboard 统计和课程卡片
- 课程首页概览
- 课程资料
- 作业/考试/通知任务
- 提问、讨论、FAQ
- AI 会话与推荐
- 错题、闪卡、学习概览

---

## 3. Teacher Demo Account

建议角色：

- 教师账号 1：有多门课程、有待处理问答、有资料、有学生预警

建议最少返回：

- Teacher Dashboard 聚合数据
- 创建课程后的邀请码
- 教师课程首页概览
- 资料列表、预览、下载、AI 解析
- 任务列表、任务详情
- 问答列表、AI 回答详情
- 学生管理
- 教师 AI 助教的会话、问题队列、反馈、工具结果、溯源

---

## 4. Admin Demo Account

建议角色：

- 管理员账号 1：有注册审核、用户管理、课程管理、内容审核和系统设置数据

建议最少返回：

- 平台概览
- 用户审核队列
- 用户列表
- 课程列表
- 审核队列
- 系统设置

---

## 5. Demo Account Identification

前端当前已经支持会话模型里的 `isDemo`。

建议后端登录或获取当前用户时返回：

- `role`
- `isDemo`
- `name`
- `id`

推荐规则：

- `isDemo = true` 时返回演示数据
- `isDemo = false` 时返回真实数据或空数据

---

## 6. Demo Data Consistency Rule

为了减少联调歧义，建议后端保证：

- 同一个 demo 账号每次进入看到的数据基本稳定
- 关键数字之间自洽

例如：

- 课程学生总数要和任务详情里的 `total` 基本一致
- 预警学生数量要和首页徽标数量一致
- 问答列表里的问题要能在 AI 问题详情里找到对应内容

---

## 7. Recommended Demo Accounts

建议至少准备：

1. 学生 demo 账号
2. 教师 demo 账号
3. 管理员 demo 账号
4. 学生空状态账号
5. 教师空状态账号
