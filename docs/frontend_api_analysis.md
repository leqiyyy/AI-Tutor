# 前端 API 依赖分析（后端先行阶段）

更新时间：2026-04-17  
分析范围：`frontend/src`

---

## 1. 结论摘要

1. 前端页面结构完整，但当前真实 API 调用覆盖很低。  
2. 登录、注册、AI 助教、通知、课程看板等大量页面仍有本地模拟逻辑。  
3. 后端当前阶段应先完成“接口契约冻结 + 全链路可运行 + 文档完备”，联调后置。  
4. 前端现有字段习惯（如 `account`、camelCase）需在后端继续兼容。  

---

## 2. 前端当前请求方式现状

| 项目 | 现状 | 影响 |
|---|---|---|
| 统一 API Client | 无 | 后续联调前必须补请求封装 |
| 统一鉴权拦截 | 无 | 登录后 token 传播缺失 |
| baseURL 环境变量 | 无统一业务 API 配置 | 联调时需统一接入 `/api/v1` |
| 请求库 | 以原生 `fetch`/本地模拟为主 | 错误处理、重试策略不一致 |
| 本地模拟 | 广泛存在（`setTimeout`、`localStorage`） | 暂不阻塞后端先行，但联调阶段需清理 |

---

## 3. 页面级依赖概览

### 3.1 已有明确 API 意图

- 注册页：`POST /api/auth/send-verify-code`、`POST /api/auth/register`（TODO）
- AI 助教相关：需要会话、消息、问答、反馈、审核接口
- 课程资料页：需要上传、列表、预览、分析、搜索、图谱

### 3.2 仍主要是本地模拟

- 登录页：本地校验后直接跳转
- 教师/学生 dashboard：课程、通知、统计多为静态数据
- 教师/学生 AI 助教组件：含本地回复生成、反馈本地存储
- 管理端看板：多数为静态统计/表格

---

## 4. 后端兼容约束（联调前先固化）

| 兼容项 | 要求 |
|---|---|
| 登录字段 | 兼容 `account`（邮箱/学号/工号） |
| 注册字段 | 兼容 camelCase 与 snake_case |
| 统一返回 | `{code, message, data}` |
| 消息溯源 | `name/page/type/score/chunk_id` 标准化输出 |
| 错误响应 | 统一错误码 + message + request_id |

---

## 5. 后端先行阶段建议

1. 先完成后端全接口能力与契约冻结（不等待前端改造）。  
2. 对前端可能依赖字段保持兼容别名，减少后续联调返工。  
3. 在 API 文档里增加示例请求/响应，前端后续可直接对照接入。
