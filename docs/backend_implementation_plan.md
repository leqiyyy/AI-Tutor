# 后端实施计划（后端先行，联调后置）

更新时间：2026-04-17

---

## 1. 目标与范围

目标：在不依赖前端联调的情况下，先完成 AI 助教后端全链路实现，达到“可运行 + 可验证 + 可扩展 + 可科研评估”。

本阶段重点：

1. 后端核心业务闭环全部可运行。  
2. RAG-Anything 查询主链真正落地。  
3. 多模态、知识图谱、反馈分析、推荐与个性化能力可测试。  
4. API 契约、技术文档、实验模板完善。  

---

## 2. 当前基线（基于仓库代码）

已具备：

- FastAPI + SQLAlchemy + Alembic 基础工程
- 认证、课程、班级、任务、聊天、审核、闪卡、分析、通知、管理端基础 API
- `SimpleRAGEngine` 与 `RAGAnythingAdapter` 双路径
- 本地存储/MinIO 适配层、健康检查、基础测试

主要缺口：

- RAG-Anything 查询主链未完全替换
- 多模态解析与图谱质量控制不足
- 反馈分析、推荐、学习路径能力未完整产品化
- 模型能力层抽象与 API/本地双轨不完整
- 交付文档尚未全部补齐

---

## 3. 分阶段计划

### Phase 0：基线校正

- 补齐 `docs` 必需文档
- 冻结 API 契约与错误码规范
- 统一 request_id/trace_id

交付：

- `frontend_api_analysis.md`
- `backend_implementation_plan.md`
- `backend_architecture.md`
- `api_contract.md`
- `rag_integration.md`
- `experiment_report.md`

### Phase 1：数据模型与迁移补齐

- 补齐权限、反馈、推荐、多模态相关表
- 迁移脚本与种子数据增强

### Phase 2：路由与服务边界补齐

- 补齐反馈分析、推荐、多模态、管理监控接口
- 统一路由分组、错误处理和响应结构

### Phase 3：AI 编排层落地

- 问题分类、上下文注入、工具路由、置信度评估
- 追问建议与资料推送能力接入

### Phase 4：RAG-Anything 主链落实

- 查询主链切换到 `aquery/aquery_with_multimodal`
- query mode 生效
- fallback 仅异常兜底

### Phase 5：多模态与知识图谱增强

- PDF/图片/音视频/PPT 统一结构化
- 图谱实体关系质量化与审核流

### Phase 6：反馈分析与推荐闭环

- 反馈统计、知识盲区识别、优化建议
- 推荐引擎、学习路径、推荐反馈回流

### Phase 7：模型能力层与双轨部署

- provider 抽象补齐
- mock/fallback 完整化
- API/本地双轨路由与可观测

### Phase 8：测试与科研评估收尾

- 单测/集成测试/回归脚本扩展
- RAG 指标评测
- 实验报告填充

---

## 4. 验收标准（每阶段最小可验证）

1. 接口可调：核心接口可通过 Swagger 或测试脚本调用。  
2. 日志可追踪：关键链路有 request_id、错误原因和耗时。  
3. 数据可落库：任务、反馈、推荐、解析结果有持久化记录。  
4. 回归可执行：新增能力至少有一条测试覆盖。  

---

## 5. 风险与降级策略

| 风险 | 降级策略 |
|---|---|
| RAG-Anything 环境依赖复杂 | 保留 `SimpleRAGEngine` 异常兜底 |
| 外部模型 API 不稳定 | provider 层超时重试 + fallback |
| 多模态解析耗时高 | 异步任务化 + 阶段性缓存 |
| 数据迁移风险 | 小步迁移 + 回放验证 + 种子隔离 |

---

## 6. 联调策略（后置）

联调将在后端能力稳定后启动，顺序为：

1. 认证与课程基础  
2. 资料与知识库  
3. AI 助教与审核回流  
4. 推荐与个性化  
5. 管理端监控与实验看板
